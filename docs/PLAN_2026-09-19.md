## 0. Compute: what runs where
| Work | Where | Needs GPU? | Cost driver |
|---|---|---|---|
| Frontier replication (GPT-6 Astra, Claude Fable 5.1 / Opus 5, Gemini) | your laptop, `harness/run_cells_v17_api.py` | no | API credits: 2,400 calls per model-pass, about $15 at $10/$50 per M tokens; reasoning passes 3-10x output tokens |
| LLM-judge grading check (R4) | laptop | no | API credits, a few dollars |
| Post-training ladder A0-A5 (R1, R2), sweep (R3) | della GPU nodes (or Azure when quota lands) | yes | 25-32 GPU-h per backbone |
| Stage measurement 13B/32B (R5), 32B arms (R6-R8) | della, multi-GPU for 32B | yes | 12-120 GPU-h |
| Behavioural-truth readout, scale table, all figures, W&B | laptop, `analysis/scale_compare.py` | no | seconds |

An API run is a Python process on your laptop that builds the same 4-turn dialogues the GPU harness builds, sends each one as a chat request, stores the reply, grades it with the same parser, and appends one JSON line per trial. Nothing is trained; nothing needs a GPU. Single pass at temperature 0, one sample per cell, snapshot id and query date stored per trial. That matches your single-seed decision: the design is deterministic on our side, and provider-side nondeterminism is reported (a 5% re-query of trials for a repeat-agreement number), not averaged away with seeds.

## 1. Architecture as it stands
```
harness/          claim banks (claims_hard.jsonl: 600 MMLU-Pro + 300 TruthfulQA; claims.jsonl: 600 SciQ) and the frozen v17
                  generator: 4 challenge kinds x 2 origins x 2 injected-confidence wordings x claim truth, greedy, 288 tokens,
                  substring grading -> cells.jsonl (one line per trial)
analysis/         analyze_v17.py (the paper's metric definitions), GEE, paper figures, and now scale_compare.py
train/            build_data.py (DPO pairs / GRPO prompts from the SAME templates), dpo.py, grpo.py (TRL + LoRA r=64),
                  reward.py (verifiable reward), eval_arm.py (arm -> v17 eval -> summary.json), configs/*.yaml
slurm/            submit_ladder.sh chains train -> eval per arm with afterok; sbatch templates; measure_stages.sh (13B/32B)
prereg/           frozen predictions H1-H8, run list, hyperparameter provenance; new: PREREG_frontier.md (draft)
results/          aggregate JSON + the 183,600 v17 per-trial records (results_v17_cells) for 17 checkpoints
```
Data flow for one arm: `build_data.py` (CPU) -> `dpo.py` or `grpo.py` (GPU, writes `<ckpt>/adapter`, `<ckpt>/merged`) -> `eval_arm.py`
(GPU, vLLM, writes `results_ladder/<tag>/<arm>/cells.jsonl` and `summary.json`) -> figures. Splits: TEST = hard qids 0-449,
DEV = 800-899 (sweep only), TRAIN = SciQ + hard 450-799.

## 3. Frontier plan (the generalisation claim)
Only lineage-free findings can transfer: (a) naming an alternative does the work of citing a source, (b) stated confidence
is unused while the challenge's truth is used, (c) revision behaviour reads out claim truth better than stated confidence.
Stage-ladder and causal claims stay at 7B-32B. Design decisions, all in `prereg/PREREG_frontier.md`:
- same 150 TEST questions, same 8 self-origin cells per claim, same grading, plus the LLM judge on every frontier trial;
- a no-reasoning pass per model and low/high effort passes for Fable 5.1 and Astra (effort is itself an axis nobody has);
- an **elicited companion** (v16 cell D: the model's own answer, then challenged). This matters more at the frontier: in
  the repo's own v16 data Qwen2.5-7B folds to bare pressure 6-25% of the time on its own answers but 58% on an injected
  claim. Injected-claim numbers are an upper bound on capitulation and the paper must say so;
- the "small vs frontier" comparison is drawn with `analysis/scale_compare.py`: log-parameter axis for 0.5B-100B open
  checkpoints, a separate categorical panel for API models (no invented parameter counts), our arms as arrows.
Publishable outcomes either way: if (a)-(c) hold at the frontier, that is the headline; if they do not, the paper reports
where the small-model phenomenon stops, which is also a result.

## 5. della integration: preemption-safe, resumable, running record
I could not fetch researchcomputing.princeton.edu today (HTTP 403 for this network, also via the Wayback Machine), so
partition names, walltime caps, QOS tiers and the preemption policy below are parameters, not facts. Paste the della page
text and I will pin them. Everything is driven by env vars: `PARTITION`, `GRES`, `CONSTRAINT`, `ACCOUNT`, `QOS`,
`TIME_DPO`, `TIME_GRPO`, `TIME_EVAL`, `SAVE_STEPS`.
What changed today, and why it survives being kicked off a node:
- **Trainers checkpoint and resume.** `dpo.py` / `grpo.py` save every `--save-steps` (50 / 25) with `save_total_limit=2`,
  auto-resume from `<ckpt>/trainer/checkpoint-*`, skip entirely when `<ckpt>/adapter` exists, and append every logged step
  to `<ckpt>/progress.jsonl` (loss, reward, lr, wall time). NOT yet smoke-tested end to end (laptop disk filled during the
  0.5B download); run the train/README.md section-0 smoke on a login node before the real submit.
- **Evaluator generates in chunks and appends.** `eval_arm.py` writes `cells.jsonl` incrementally with a trial index and
  resumes from it; `train/test_eval_equivalence.py` proves it emits exactly the frozen harness's 10,800 dialogues. The
  legacy one-shot path is still there behind `--harness-subprocess`.
- **Slurm templates**: `--requeue`, `--open-mode=append` (logs survive requeue), `--signal=B:USR1@180` (a trap logs the
  eviction), `--kill-on-invalid-dep=yes` on every dependent so a failed trainer does not leave its eval pending forever.
  `_common.sh` no longer builds a venv on compute nodes (fails fast), points `HF_HOME` at `/scratch/gpfs/$USER/hf`, and
  runs Hugging Face fully offline (`RM_ONLINE=1` to override). `slurm/prefetch.sh` downloads every model and dataset and
  builds the training data on a login node first.
- **Running record.** After each finished arm, `eval_arm.py` regenerates `results/scale_table.csv` and `figures/scale/*.png`
  (and W&B if enabled); `results_server.py` still serves the dashboard through the SSH tunnel. Nothing is lost between
  arms, and a partially finished arm leaves its `cells.jsonl` and `progress.jsonl` behind.
Open item once the page text is in hand: choose the partition (A100 80 GB vs H100 nodes), set `TIME_GRPO` under the cap
(GRPO arms are 6-9 h; `grpo.epochs 0.5` if the cap is shorter), and decide whether a low-priority preemptable partition is
worth using now that requeue is safe.

## 6. What the autoresearch harness contributed
`autoresearch-loop` got a `scripted` researcher and a CPU task (`contrib/tasks/rm_behavioral_truth`) built from the 183,600
v17 trials. Nine pre-registered proposals, strict keep/revert: a claim's 12 challenge outcomes predict whether the claim
is true at 0.744 held-out AUROC (leave-one-family-out), against 0.675 for the plain retain rate and 0.47-0.70 for the
models' own verbalised confidence. Per checkpoint: Qwen-14B 0.89, Phi-3.5 0.88, Qwen-7B 0.86. Every aggregator after the
first plateaued within 0.002: the headroom is in new behavioural cells (sequential pushbacks, paraphrased challenges,
fresh-context re-ask), not better aggregation. This is the strongest form of the abstract's "resistance predicts
correctness" sentence and a natural Section 5. The same harness can drive reward-shaping search on DEV once GPUs exist,
kept separate from the pre-registered arms.

## 7. W&B
`python3 analysis/scale_compare.py --wandb` logs the unified table, per-model summary metrics and the four figures to
project `reality-monitoring`; offline until `WANDB_API_KEY` is set, then `wandb sync wandb/offline-run-*`. Add rows to
`META` in that script as new sizes are measured (27B, 32B, 70B, 100B); API models are picked up automatically from
`results_api/*/`.
