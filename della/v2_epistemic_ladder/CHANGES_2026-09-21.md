# v2 epistemic ladder: imported from co-author A's della package (2026-09-17) with two fixes (2026-09-21)

Package origin: `pkg 2` sent by co-author A; self-contained, not in the repo layout. `secrets.env` (HF token) is NOT imported and is
git-ignored; the token should be rotated because the file has been passed around.

## What it measures
Scale ladder 0.5B-72B (14 models, 4 families): does declared epistemic state {none, low, high, 30%, 90%, verified, guess}
move revision, for claims from self / user / another AI, across 3 domains and 3 template families (C held out), with a
forced-choice knowledge baseline and genuinely-sampled own claims. ~126k generations per model; ~45-60 A100-hours.

## Fixes applied
1. **Matched-position origins** (`user_matched`, `other_ai_matched`). In the original, origin=self puts the claim in a
   prior assistant turn and the challenge in a new turn, while user/other_ai put claim and challenge in ONE user message.
   The pre-registered v17 control (prereg/PREREG_v17_controls.md) showed the resulting "self-claims are cheaper to abandon"
   effect reverses when position is matched: it was recency, not source. The matched origins reproduce the v17 construction
   (claim in a prior user turn, neutral acknowledgement, challenge in a new turn). Unmatched origins are kept for comparison.
   Cells per question: 84 -> 140.
2. **Harmful/beneficial split** in `analyze_v2.py`: every state-use and origin contrast is now reported pooled (legacy) AND
   separately for truth=True (abandoning a correct claim, harmful) and truth=False (accepting a correction, beneficial); the
   summary table shows the harmful versions. This is the audit's issue 2 (docs/reviews/2026-09-21/review.pdf).

## Caveats before running
- All epistemic states are INSERTED text (audit issue 1). The ladder measures use of supplied metadata; it does not measure
  use of the model's own elicited confidence. Pair with `experiments/run_identification.py` for that.
- Bank overlap: `claimbank_v2.py` draws 400 TruthfulQA mc1 items; the paper's training slice (claims_hard 450-899) contains
  300 TruthfulQA items from the same 817-item set. Fine for untrained checkpoints; do NOT evaluate trained arms (STAND, D2,
  FIRM) on this bank without removing the overlap.
- `prepare.sh` pip-installs vllm unpinned; on della use the repo venv (`train/requirements.txt`) instead. 450 GB of
  downloads; `SKIP_BIG=1` drops 32B/72B/70B. Anaconda module name is hard-coded (2024.10); `_common.sh` handles fallbacks.
- Post-audit priority: this is a scale ladder of inserted metadata; the della spec (della/DELLA_SPEC.md) now ranks D2 and
  the identification wave above another ladder. Run the 4 anchor models + 32B/72B at most, as the scale panel.
